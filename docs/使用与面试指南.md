# 电动矿卡能耗预测与仿真分析系统：使用与面试指南

## 1. 项目概览

本项目基于电机效率 MAP 与车辆纵向动力学模型，对电动矿卡在典型矿山工况下的能耗进行逐秒仿真。系统将计算模型封装为 FastAPI 接口，并使用 ECharts 提供可交互的网页可视化。

核心能力包括：

- 三种典型工况仿真：重载上坡、平路满载、长下坡回收；
- 电机转速-转矩效率 MAP 查表与边界处理；
- C-rate 相关的电池充放电效率；
- SOC 时程、累计能耗、工作点轨迹与能量损耗分解；
- 恒定效率模型与效率 MAP 模型的结果对比；
- 参数敏感性分析、自定义工况和多车型对比。

## 2. 环境与启动

### 2.1 环境要求

- Python 3.10 或更高版本；
- 支持 `pip` 的命令行环境；
- 浏览器（Chrome、Edge 等）。

### 2.2 安装依赖

在项目根目录执行：

```bash
python -m pip install -r requirements-dev.txt
```

`requirements.txt` 是运行所需依赖；`requirements-dev.txt` 在此基础上额外安装测试依赖。

### 2.3 启动网页

```bash
python -m uvicorn backend.app:app --reload
```

打开浏览器访问：

```text
http://127.0.0.1:8000
```

接口交互文档位于：

```text
http://127.0.0.1:8000/docs
```

首次运行时，仓库中已包含默认效率 MAP 与标准工况数据，无需 MATLAB 环境。

## 3. 网页使用说明

### 3.1 车辆参数

左侧面板支持修改整备质量、滚动阻力系数、传动效率、电池容量和初始 SOC 等参数。修改后点击“重新仿真”，右侧所有卡片和图表会同步更新。

“车型预设”提供 60 吨级、90 吨级和 110 吨级参数组合；选择后仍可继续手动微调。

### 3.2 结果阅读

页面顶部的结果卡片展示每个标准工况的：

- 净能耗：正值代表消耗电池能量，负值代表回收能量大于消耗；
- 驱动能耗与回收能量；
- 功率加权平均电机效率；
- SOC 变化量。

“电机效率 MAP 与工作点轨迹”图中，颜色代表效率区间，黑色虚线为外特性边界，散点为该工况的实际电机工作点。工作点落在不同区域，会直接影响电池端能耗。

### 3.3 效率模型对比

“效率 MAP 与恒定效率模型对比”图使用相同的工况、传动效率和电池效率，只改变电机效率建模方式：

- 效率 MAP：电机效率随转速和转矩变化；
- 恒定效率：电机效率固定为 90%。

图中标签显示恒定效率模型相对于 MAP 模型的能耗偏差。该图用于说明：对重载爬坡、低速大转矩等非高效工作点，固定效率假设可能带来明显偏差。

### 3.4 自定义工况

在左侧“自定义工况”区域输入最高速度、加速/匀速/减速时间、坡度和载重，点击“生成并仿真”。系统会生成一条梯形速度曲线，并将其接入工作点图、时程图与能量分解图。

## 6. 常见问题

按 `Ctrl + F5` 强制刷新浏览器缓存。开发模式下，后端代码会自动重载；修改前端静态文件后通常只需刷新页面。

```bash

```

再访问 `http://127.0.0.1:8001`。

```bash
python -m pip install -r requirements-dev.txt
```

## 7. 面试时的项目介绍

### 60 秒版本

我将电动矿卡能耗计算模型实现为 Python Web 项目。系统首先根据车速、坡度、载重和加速度计算车辆纵向动力学需求，再得到电机转速和转矩；随后通过二维效率 MAP 插值得到电机效率，并结合传动效率与 C-rate 相关电池效率，逐秒积分得到能耗和 SOC。后端使用 FastAPI 提供仿真接口，前端使用 ECharts 展示工作点、能耗、损耗分解和敏感性分析。我还加入了恒定效率模型对比，用于量化简化效率假设对不同矿山工况能耗预测的影响，并用 pytest 和 GitHub Actions 验证核心结果。

### 高频问题与参考回答

#### 1. 为什么不用一个固定电机效率？

固定效率计算简单，但电机效率会随转速和转矩变化。矿卡在重载上坡时经常处于低速、大转矩区域，效率与高效区差异明显。使用效率 MAP 可以反映工作点变化，因此比固定 90% 效率更适合分析不同工况下的能耗趋势。

#### 2. 从工况到电池能耗的计算链路是什么？

输入是速度、加速度、坡度和载重。先计算滚动阻力、空气阻力、坡度阻力和加速阻力，得到轮边需求功率；再根据轮速和传动比得到电机转速、转矩；用效率 MAP 查询电机效率；最后叠加传动效率和电池充放电效率，得到电池端功率，并使用梯形积分计算累计能耗。

#### 3. 为什么使用二维插值？

效率数据储存在离散的转速-转矩网格上，而仿真工作点通常不刚好落在网格节点。二维线性插值能在相邻节点之间平滑估算效率，避免把效率突变带入能耗积分。对于超出网格边界的点，项目采用针对高速、低速和过载情形的边界衰减处理。

#### 4. 电池效率是怎样处理的？

项目用功率除以电池容量得到 C-rate。放电和充电采用不同的效率衰减系数，并对低功率和效率上下限做保护。这样高功率爬坡和长下坡回收时，电池效率不会被简单视为一个恒定数。

#### 5. 为什么使用梯形积分？

功率是离散时间序列。梯形积分使用相邻两个采样点的平均功率计算该时间段能量，相比直接用单点矩形法更平滑，也更适合处理加速、减速时的功率变化。

#### 6. 恒定效率模型对比的意义是什么？

它在所有其他计算条件相同的情况下，只把变效率 MAP 替换为恒定 90% 效率。因此两组结果的差异可以直接归因于电机效率建模方式，而不是车辆参数或工况不同。这是验证“效率变化是否值得被建模”的直观证据。

#### 7. 你如何保证 Python 结果可信？

我将核心计算拆分为动力学、效率查询、电池效率和仿真积分等独立模块，为典型工作点、边界条件和完整工况添加单元测试；接口层也有集成测试。CI 会在多个 Python 版本上自动运行这些测试，避免后续修改破坏已有结果。

#### 8. 项目中最有挑战的部分是什么？

难点是让各模块的功率方向和效率使用方式保持一致。驱动时，电机和电池效率表现为“机械功率需要除以效率”；回收时，能量从车轮流回电池，效率表现为“机械功率乘以效率”。如果符号或方向处理不一致，就会导致下坡回收能量错误。

#### 9. 前后端如何分工？

后端负责数值计算、数据加载和接口输出，前端只负责参数输入和图表渲染。这样核心模型可以被测试和复用，未来也可以被命令行工具或其他客户端调用，而不依赖网页页面。

#### 10. 项目的局限性是什么？

当前工况是典型合成工况，效率 MAP 基于已知特征构造，主要用于比较不同效率建模方法对结果趋势的影响；它不是针对某一台具体车辆、某一路线的台架标定工具。下一步可以用实测道路、载重和效率数据进行标定，并进一步加入电池温度、SOC 约束和再生制动功率限制。

#### 11. 如果让你继续做，会优先做什么？

我会优先接入真实运行数据并建立参数标定流程，因为这能把目前的趋势分析提升为特定车辆的预测工具。工程上会进一步补充输入校验、结果导出和部署配置。

#### 12. 这个项目体现了哪些能力？

它体现了把算法模型工程化的能力：将数值计算模块化、提供 API、完成前端可视化、编写测试并配置持续集成。同时也体现了对业务问题的理解，即通过对比实验说明为什么效率 MAP 会影响矿卡能耗预测结果。

## 8. 面试表达提醒

- 如实说明效率 MAP 的数据来源和模型适用范围，不夸大为实际车辆的绝对精确预测；
- 先讲“问题-方法-结果-工程化”，再展开公式和代码细节；
- 演示时优先展示重载上坡与恒定效率对比图，它最容易说明项目价值；
- 被问到不确定的问题时，可以明确当前模型假设，并说明下一步可验证或改进的方向。
